# Local Docker driver qualification

On 2026-10-18, the opt-in qualification script exercised the Docker Engine driver with the already-local official Node image `docker.io/library/node@sha256:3638d9a6fe4030bd716be989438248074489337ba3275657f93595428be4fc03`. This is the exact image digest used for the run; it is not the image digest pinned by the repository Dockerfile. The run used Docker client 29.2.1 and Engine 29.9.0, and performed no image pull, build, or push.

The driver now accepts only the exact Engine `/info` seccomp capability value `name=seccomp,profile=builtin`; it rejects unconfined, custom, duplicate, or unknown seccomp values. Per-container inspection also requires the only `SecurityOpt` entry to be `no-new-privileges:true`, so no container-level seccomp override is present. Docker's container inspection does not expose the effective inherited syscall filter, so this qualification confirms the daemon's reported built-in profile and the absence of a per-container override; it does not test syscall denial behavior.

The [qualification script](https://github.com/metaneutrons/HASI/blob/2703005aaf3c420335d0e87a1b4044e254a5a41a/scripts/qualify-plugin-container.ts) passed its read-only-root-filesystem, non-root UID/GID, capability-drop, resource-limit, and non-internal-network denial probes without creating a container. Its admitted stage confirmed UID/GID `65532:65532`, read-only root filesystem, `CapDrop=ALL`, no added capabilities, `no-new-privileges`, CPU/memory/swap/PID limits, and a host port bound only to `127.0.0.1`. Reconciliation found the exact staged container, cleanup removed it, and the script verified that all pre-existing container IDs remained unchanged and its temporary networks were removed.

The qualification routing callback is a synchronous in-memory journal used only by this script. Production wiring must provide a durable route-operation journal whose `committed` and `not-committed` states are terminal and fenced against later commits; this Docker run does not qualify an external routing service. The official Node image has no plugin HTTP fixture or `/healthz` endpoint, so the bounded health probe returned `false`. This run therefore does not qualify a running plugin, successful health checks, or application-level denial behavior.

The paired-relay repair replaces this Node-only admission probe with `scripts/qualify-healthy-plugin-container.ts`. The result above belongs to the linked historical revision; it does not qualify the current driver or a healthy MCP process.
