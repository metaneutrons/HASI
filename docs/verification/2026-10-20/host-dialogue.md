## Boundary and repair

Protected autosaves previously removed browser-generated greetings, workplace
refinements and missing-detail prompts as unsigned assistant text. The storage
boundary was correct; the producer lacked a separate display authority.

The protected `/api/chat/dialogue` accepts only closed typed operations. It
cannot sign submitted text, counts, cards, URLs or arbitrary error bodies.
Static copy belongs to the host; result-dependent copy is generated by the shared
pure room planner from authenticated server resource reads. Empty-booking copy
requires a successful authenticated empty read and describes that historical
query, not a permanent empty state.

A distinct HKDF/HMAC domain binds display text/code, subject scope, conversation
and message identities, expiry and current history authority. Search-dependent
receipts bind the complete authorized catalogue and ordered candidate IDs. Every
protected load/save rechecks authority, requires catalogue availability and
reconstructs candidate metadata with unchecked availability. Changed or denied
catalogues redact affected content; denied reads are never treated as successful
empty catalogues. The maximum receipt lifetime is 30 days. Native availability
and proposal confirmations retain their existing separate authorities.

Host notes and action helper text are excluded from model history. Even a
reshaped, schema-valid knowledge-evidence envelope using the host receipt fails
its signature check. This mechanism grants no model, source, plugin or action
permission. Ordinary mock-persona development/public fixture history uses the
same pure planner without pretending to establish protected identity authority.

The neutral office request “Einzelbüro oder geteiltes Büro ist mir egal” now
retains both choices and contributes no residual name query. Named greetings
such as “Hallo HASI!” are recognized. Relative dates in the Dialog-Demo now use
the stamped user-event time, matching the online path.
